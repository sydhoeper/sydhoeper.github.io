Local design system · Version 0.5 · Updated August 2026

A shared language for Syd’s portfolio.

This living reference documents the visual and interaction decisions already used across the website. It is intentionally practical: complete enough to keep current pages cohesive, and flexible enough to grow with the portfolio.

Principles

The system should feel warm, direct, expressive, and usable. Editorial typography gives the work personality; restrained components keep that personality from competing with the projects.

01 · Clarity

Let the work lead

Use generous space, direct labels, and predictable hierarchy so project imagery and outcomes remain the focus.

02 · Character

Warm, not sterile

Cream surfaces, deep aubergine text, and Fraunces headings create a distinct editorial voice without reducing utility.

03 · Access

Make states obvious

Links look like links, focus is visible, controls have names, and interactions never depend on color alone.

Layout

The desktop shell uses a persistent 300-pixel navigation rail and a focused content column. Below 850 pixels, navigation becomes a sticky compact header and content uses a 24-pixel page inset. The footer follows the same responsive shift.

Page shell

Focused width

Keep narrative content within the shared 1,050-pixel main column unless immersive media needs more room.

Section pattern

Heading left, copy right

Use the recurring split heading for major case-study sections, then stack it at narrow widths.

Responsive rule

Reflow, do not shrink

Collapse grids to one column, preserve readable type, and allow media controls to remain comfortably tappable.

Current breakpoints The shared shell changes at 850 pixels. Dense galleries and small media controls simplify again at 560 pixels. Case-study components may use container queries when their available column matters more than the viewport.

Progressive disclosure

Dense supporting material uses native details and summary. The summary is pill-shaped, keeps visible focus, and changes both its label and chevron when opened.

View supporting details

Supporting research, extended process notes, or secondary artifacts belong here when they would otherwise interrupt the primary story.

Interactive embeds

Playable projects sit in a dark, rounded stage that preserves the source aspect ratio and scales the iframe to the available column. Every iframe needs a useful title, a fallback link, and fullscreen permission when the experience supports it. Audio-heavy work includes an adjacent stop-and-restart control.

Case-study navigation

Previous and next project cards close long case studies. Direction is an eyebrow label, the project title is set in Fraunces, and narrow containers stack the pair into one column.

Implementation

The website is a small, framework-free system. Shared tokens and component styles live centrally; page fragments add only the layout or media treatment unique to that story.

style.css

Source of truth for foundations, the page shell, navigation, footer, shared cards, galleries, lightbox, carousel, disclosures, case-study navigation, focus states, and responsive behavior.

index.html

Owns the persistent semantic shell: skip link, sidebar navigation, main content target, footer, mobile overlay, and gallery dialog.

script.js

Loads page fragments, synchronizes navigation state, manages the mobile menu, sizes embeds, initializes carousels, controls the gallery dialog, and restores focus after interactions.

pages/

Contains the individual project and gallery fragments. Local styles are acceptable for genuinely one-off artifacts; repeated patterns should move into the shared stylesheet and this reference.

Navigation

Hash-routed pages

Internal project links update the URL hash and load fragments into the persistent shell. Local jump links use explicit scroll targets.

Media

One behavior layer

Images, videos, carousel slides, and product galleries share centralized initialization so dynamically loaded pages behave consistently.

Exceptions

Document repetition

When a local pattern appears twice, promote it to a shared token or component and record its states, breakpoint behavior, and accessibility contract here.

Accessibility standards

Accessibility is part of every component definition, not a later review. The portfolio follows these interaction, content, and release standards whenever a page or pattern is added.

Keyboard & focus

Everything works without a pointer

Use native controls, logical focus order, visible focus rings, and expected keys. Opening navigation, disclosures, galleries, and carousels must never trap or lose focus.

Color & states

Never communicate through color alone

Pair color changes with underlines, weight, borders, labels, icons, or movement. Text, controls, and meaningful UI states must retain readable contrast.

Structure & media

Make the page understandable

Use semantic headings, descriptive links, useful alternative text, labeled dialogs and carousels, native video controls, and captions whenever speech carries meaning.

Motion & effects

Keep delight optional

Respect reduced-motion preferences, hide decorative effects from assistive technology, keep the ribbon behind content, and leave the sparkler cursor off until someone chooses it.

Implementation checklist
  • Semantic headings follow a meaningful hierarchy.
  • Every function is reachable with a keyboard.
  • Focus remains clearly visible on all interactive elements.
  • Selected and hover states do not rely only on color.
  • Body text and controls maintain readable contrast.
  • Tap targets meet a 24-pixel minimum; 44–48 pixels is preferred.
  • Motion respects reduced-motion preferences.
  • Decorative imagery and motion are hidden from assistive technology.
  • Optional effects, including the sparkler cursor, default to off.
  • Images, videos, dialogs, and carousels have useful accessible names.
Release check

Before publishing a page

  • Navigate the entire page using Tab, Shift+Tab, Enter, Space, and arrow keys where expected.
  • Review at 320, 768, and 1,440 pixels without horizontal page scrolling.
  • Confirm zoom at 200% preserves content and controls.
  • Check alternative text, link purpose, labels, and media behavior.
  • Verify new values use a system token or are documented as a deliberate exception.
